## Hard rules (enforced by `design-lint` in pre-commit + CI)

1. **No hardcoded colors.** Every color must reference a token (`var(--color-*)`). Raw
   hex literals not present in the token system fail the build.
2. **No off-scale spacing.** Use the spacing scale. Tailwind arbitrary `px` values that
   are not a scale step fail the build.
3. **No unknown components.** Only import components listed in the manifest's `components`
   inventory. To add one, build it into the design system first, then re-run
   `/steve-designer:enforce` (or `ingest_design_system.py`).
4. **No literal UI strings** when the manifest declares i18n (`i18n.enabled === true`).
   Every string must read from an i18n key.

## Required states

Every screen covers loading / empty / error / success, plus its domain states. See
`docs/design/design-doc.md` §5 and `docs/design/screens.md` for the per-screen matrix.

## Laws of UX

UI changes follow the Laws of UX as checkable rules `UX-1` … `UX-18` (Hick, Fitts,
Jakob, proximity, Miller, Doherty, Von Restorff, serial position, peak-end, Zeigarnik,
Prägnanz, similarity, uniform connectedness, Tesler, Postel, Parkinson, Occam, Pareto),
defined in `docs/design/laws-of-ux.md`. Blocking: hit targets below 24×24 px, and
async actions that lack a pending state or a double-submit guard. Everything else is a
review warning unless `docs/design/design-doc.md` §10 nails it down. A deliberate
exception is documented in the design doc, never taken silently.

## Halt and ask

A missing design decision — token, component, or copy — is a stop, not an improvisation.
Record it in `docs/design/decisions.md` as a pending row and return to the director.
